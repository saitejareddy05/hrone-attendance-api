# REVIEW.md

Defects found in the starter `app/main.py`, each with a concrete failing example and the fix.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `MongoClient(...)` | Created without `tz_aware=True`, so every datetime read back is naive. Epoch-ms conversion and IST maths then silently use the server's local zone. | `punch_in` of a seeded record comes back 5h30 off when the host is not UTC. | `tz_aware=True, tzinfo=UTC`; all conversion goes through `dt_to_ms` / `ms_to_ts`. |
| 2 | startup | No indexes at all, and no uniqueness guarantee on `emp_code` or `(emp_code, date)`. | `GET /attendance` on 100k docs is a COLLSCAN; duplicate rows can be inserted. | `ensure_indexes()` at startup (idempotent, never crashes the app); unique indexes carry the guarantees. |
| 3 | `/health` | Always returns `ok`, even when MongoDB is down. | Stop MongoDB, still get 200. | Pings MongoDB; 503 on failure. |
| 4 | `compute_late_minutes` | Builds `start` with `punch_in.replace(...)`, i.e. in the datetime's own zone (UTC/naive), not IST. Converts to int minutes *before* the grace test, so 09:40:01 gives 10 min -> not late (`> 10` is false) while the rule says late. Ignores overnight shifts. | 09:40:01 on shift 09:30 should return 10; starter returns 0. | `shift_window()` builds IST datetimes (next-day end for overnight); the grace test is on whole seconds (`> 600`), then floor to minutes. |
| 5 | `compute_work_hours` | `round()` on a float: banker's rounding plus binary float error (`2.675` gives `2.67`). | 4h30m18s = 4.505 h should be 4.51. | `Decimal` with `ROUND_HALF_UP` (`round_half_up`). |
| 6 | `compute_overtime` | No 30-minute minimum (R3); date taken from the stored date so an overnight shift end lands on the wrong day. | Punch-out 10 min after shift end gives 10, should be 0. | Uses the shift window's real end; returns 0 below 30 min. |
| 7 | all helpers | Instants are not truncated to whole seconds (R1); there is no half-day rule at all (R5). | `punched_at` with .900 ms is stored with the fraction. | `ms_to_ts()` truncates; `compute_half_day()` added; `derive_fields()` is the one place all four values are computed. |
| 8 | `POST /employees` | Check-then-insert races: two concurrent creates can both pass `find_one`. `created_at` is naive local time and returned as a datetime, not epoch ms. No input validation (code pattern, email, `HH:MM`, real dates, `shift_start != shift_end`). | 20 parallel creates -> several 201; `emp_code: "x"` accepted. | Unique index + `DuplicateKeyError` -> 409; Pydantic constraints from the contract -> 422; UTC `created_at` returned in ms. |
| 9 | `GET /employees` | `skip = page * page_size` skips one page too many. `total` counts the whole collection, not the filter. No sort. No bounds on `page` / `page_size`. | `page=1` never shows the first rows; `total` ignores `department`. | `(page-1)*page_size`; `count_documents(filter)`; `sort emp_code`; `ge=1`, `page_size<=100` -> 422. |
| 10 | `POST /attendance/punch-in` | Unknown employee: `emp` is `None`, `emp["shift_start"]` raises -> 500 instead of 404. | `emp_code: "NOPE"`. | `get_employee()` -> 404. |
| 11 | `punch_in` (date) | `datetime.fromtimestamp(ms/1000)` uses the server's local zone, so the date is not the IST date. Overnight rule missing. `if body.punched_at` treats 0 as "not sent". | 01:00 IST punch-in (previous day in UTC) lands on the wrong date; 02:00 on a 22:00-06:00 shift must belong to the previous day. | `attendance_date()` (IST + overnight rule); `is not None` check. |
| 12 | `punch_in` (race) | `find_one` then `insert_one` is check-then-insert. | Two simultaneous identical punch-ins both get 201 (needs the unique index too). | Unique `(emp_code, date)` index; `DuplicateKeyError` -> 409. Exactly one 201. |
| 13 | `punch_in` (validation / output) | `status` is a free string (`ABSENT`, `LEAVE`, garbage accepted); `punched_at` not range/type checked (seconds, floats, strings). Response leaks `id`, returns datetimes instead of ms. | `status: "LEAVE"` returns 201; `punched_at: 1783312500` accepted. | `Literal` presence statuses, strict int in `[1e11, 4.1e12]` -> 422; `record_out()` is the single serializer (no `_id`/`id`, ms instants). |
| 14 | `GET /attendance` | `list(find(q))` loads the whole collection into memory and sorts and paginates in Python. Sort is `date` only (no `emp_code` tie-break). No date validation, `date_from > date_to` not rejected. `total` fine but built from the in-memory list. Leaks `id`; legacy docs without `history` / `half_day` would be returned as-is. | 100k docs: slow and memory heavy; unstable page order for equal dates. | DB-side `sort` + `skip` + `limit`, `count_documents`; indexes serve the sort; 422 on bad/inverted dates and bad `status`; `record_out()` applies defaults for legacy docs. |
| 15 | whole file | Sync handlers are fine, but nothing handles `DuplicateKeyError`, `PyMongoError`: any DB hiccup becomes a 500. | MongoDB down mid-request. | Global handler returns 503; expected errors are mapped to 404/409/422. |

## Looked at and decided it is not a defect
* `IST = timezone(timedelta(hours=5, minutes=30))`: correct (no DST in India); a fixed offset is fine.
* Plain `def` (not `async def`) endpoints with the blocking PyMongo driver: FastAPI runs them in a thread pool; PyMongo's client is thread-safe. Fine for concurrency.
* Storing dates and shift times as `YYYY-MM-DD` / `HH:MM` strings: correct per DATA_MODEL.md, and ISO strings compare correctly in range queries.
* `doc.pop("_id")` after `insert_one`: the intent (do not leak `_id`) was right; the `id` field added elsewhere was the bug.
* Reading `dotenv`: `load_dotenv()` does not override real environment variables by default; I made that explicit with `override=False`.
